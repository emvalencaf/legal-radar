# Manage prompts and trace queries in a local Langfuse, and publish the report on GitHub Pages

Issue #1 left three things open: prompt-management/observability tooling, and where the static report lives. Issue #8 made the per-call wide-event log the single source of truth for usage. The tooling had to run locally and for free, like Neo4j (issue #12). LangSmith was considered first, but self-hosting it requires an Enterprise license, and its free cloud tier is account- and quota-bound.

## Decision

- **Langfuse, self-hosted via `docker compose`, is the prompt registry and tracing backend.** It runs next to Neo4j and is only needed when a developer wants prompt editing or traces.
- **Prompts live in Langfuse**, fetched by a **pinned version number** (never the moving `production`/`latest` label). A **lockfile** with a snapshot of each prompt is versioned in the repo; tests, CI and runs without Langfuse read the lockfile and never touch the network. The snapshot hash goes into the wide event and into the enrichment idempotency key (ADR-0002, ADR-0003), so changing a prompt returns only the affected LLM-processed chunks to `pending`.
- **Tracing in Langfuse covers query-time (LangGraph) and evaluation only.** Ingestion and enrichment stay on wide events, which remain the single source of truth for usage (issue #8); tracing them would duplicate that log. Tracing is optional: with Langfuse off the pipeline runs identically, from the lockfile.
- **`assayer` needs a Langfuse sink.** Its current integration only pushes to LangSmith; since `assayer` is our own library, we add an equivalent Langfuse integration rather than depend on LangSmith.
- **The report is static HTML generated by the pipeline and published on GitHub Pages** by a manual `make`-style command; no CI.
- **The report carries no links to traces.** Traces live in a local Langfuse that readers cannot reach. It embeds the prompt hash, the run id and the metrics instead.

## Consequences

- No account, quota or network dependency: everything runs locally.
- Langfuse's compose stack is heavy (web, worker, Postgres, ClickHouse, Redis, MinIO) and is not meant for production; acceptable for a demo, and it is optional.
- Langfuse's own prompt-to-trace linking is documented as unavailable with the LangChain integration and when a fallback prompt is used, so the link between a trace and its prompt is the prompt hash in the wide event, not Langfuse's UI link.
- Langfuse and `assayer` integration work is new code (issue to be filed).
- Changing a prompt means a new Langfuse version plus a lockfile update; the lockfile is the review surface in PRs.
